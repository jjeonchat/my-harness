# R3 — 하네스 파이프라인

사용자가 모든 기본값을 승인하고 저장을 요청했다. 실제 작업 순서는 `../story-workflow.md`, 실행 단위와 완료 기준은 `harness-R2-purpose.md`를 따른다.

## 단계별 입출력

| 단계 | 입력 | 출력 |
|---|---|---|
| 1. 레퍼런스 수집·분석 | 대상 흐름, 화면 목록, 경쟁사 레퍼런스 | 레퍼런스 목록, 분석 내용, 반영할 부분 |
| 2. 화면 설계 | 분석 내용, 반영할 부분 | 화면 설계서 |
| 3. 키스크린·컨셉 확정 | 화면 설계서, 레퍼런스 | 390×844 키스크린 2~3개, 컨셉 승인 기록 |
| 4. 디자인 확장 | 승인된 컨셉, 화면 설계서 | 디자인 토큰, 컴포넌트, 합의한 전체 화면 디자인 |
| 5. 검토 | 완성된 디자인, 토큰·컴포넌트 | 검사항목별 판정 결과, 수정 대상 목록 |

`../prd.md`, `../story-service.md`, `../design.md`는 각 단계의 판정 기준으로 적용한다. 서비스 목적과 실제 작업 과정을 혼합하지 않는다.

## 레퍼런스 수집 시작점

- 본인이 시작 URL 또는 캡처를 제공하고, 에이전트가 수집·분석한다.
- 접근할 수 없는 자료는 기록한다.
- 분석 가능한 자료가 0개이면 1단계에서 중단한다.

## 컨셉 미승인 시 복귀

| 사유 또는 상태 | 처리 |
|---|---|
| 시각 표현 문제 | 3단계로 돌아간다. |
| 화면 구성·기능 누락 문제 | 2단계로 돌아간다. |
| 승인 기록 없음 | 4단계 진행을 막는다. |

## 최종 검토 실패 시 복귀

| 사유 | 처리 |
|---|---|
| 토큰·컴포넌트·화면 표현 위반 | 4단계로 돌아간다. |
| 화면 설계 자체의 누락 | 2단계로 돌아간다. |
| 수정 완료 | 5단계를 다시 실행한다. |
| 컨셉 변경 | 3단계에서 재승인받는다. |

## 후속 확정 사항

- 단계별 파일명, 규칙의 단일 기준 파일, 재개 방식은 R4의 `harness-R4-artifacts.md`를 따른다.
- 기계 판정 조건, 승인 기록의 판정 방식 등 게이트 세부 사항은 R5에서 확정한다.
