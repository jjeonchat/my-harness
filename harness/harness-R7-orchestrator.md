# R7 — 오케스트레이터

사용자가 모든 기본값으로 진행하도록 승인했다. 이 문서는 오케스트레이터의 실행 위치, 기록 권한, 실행 순서와 중단·재개 규칙을 확정한다. `CLAUDE.md`는 R8까지 마친 뒤 초안을 보여주고 별도로 승인받는다.

## 실행 지침과 위치

- 하네스 실행 지침은 `harness/CLAUDE.md`에 둔다.
- Claude Code는 `harness/` 폴더에서 실행한다.
- PRD·디자인·스토리 문서는 상위 폴더에서 읽는다.

## 역할과 기록 권한

- 오케스트레이터는 작업 배정, 게이트 실행, 상태 기록을 담당한다.
- 단계별 작업물은 담당 작업자에게 맡긴다.
- 기준 문서와 `rules.json`은 읽기만 한다.
- 판정 결과를 임의로 통과로 바꾸거나 사람 승인을 대신하지 않는다.

다음 경로는 `harness/runs/<실행ID>/` 기준이며, 오케스트레이터가 직접 기록할 수 있는 범위다.

| 경로 | 기록 내용 |
|---|---|
| `input.json` | 해당 실행의 입력 |
| `run-state.json` | 실행 상태, 해시, 재시도 횟수 |
| `03-concept/approval.json` | 해당 실행·컨셉 버전에 대한 사용자의 명시적 승인 |
| `05-review/` 안의 결과 파일 | 판정자가 반환한 검사 결과와 리뷰 |

## 실행 순서

1. 레퍼런스 수집·분석
2. 화면 설계
3. 키스크린 제작
4. 사용자 컨셉 승인 확인
5. 디자인 확장
6. 최종 검토

위 순서는 R3의 1→2→3→컨셉 승인→4→5 순서를 의미한다. 컨셉 승인은 3단계의 게이트이며 별도 작업 단계로 추가하지 않는다.

- 동시에 실행하는 작업자는 최대 1개다.
- 단계 완료 시 산출물과 해당 단계의 필수 조건을 확인한다.
- 미통과 또는 판정 불가가 있으면 다음 단계로 넘어가지 않는다.

## 중단·재개·실패 처리

- 실행 상태, 입력·규칙·산출물의 해시, 재시도 횟수를 기록한다.
- 재개 시 변경된 단계부터 다시 수행한다. 변경된 단계 이후의 단계도 R4의 재개 규칙을 따른다.
- 실패 시 R3의 복귀 규칙을 적용한다.
- 검사 항목별 연속 자동 수정은 최대 2회다.
- 2회 수정 후에도 실패하면 중단한다.
- 재개만으로 재시도 횟수를 초기화하지 않는다.
- 컨셉 변경 시 기존 승인으로 진행하지 않고 같은 승인 지점에서 재승인받는다.
