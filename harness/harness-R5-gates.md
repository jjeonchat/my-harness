# R5 — 하네스 게이트

사용자가 모든 기본값과 저장을 승인했다. 이 문서는 판정 조건과 증거, 사람 승인 지점, 실패 처리를 확정한다. 실행용 `rules.json`과 판정 스크립트는 아직 생성하지 않는다.

## 판정 증거와 기본 조건

- 화면 설계의 구조화 데이터와 Figma에서 직접 읽은 노드 속성을 검사한다.
- 키스크린 수는 2~3개여야 한다.
- 키스크린 크기는 모두 390×844여야 한다.
- 합의한 화면 목록 대비 누락은 0개여야 한다.
- 증거 누락이나 조회 실패는 `판정 불가`로 기록하고 통과를 막는다.

## 서비스 필수 원칙 검사

판정 근거는 `../story-service.md`와 `../prd.md`다. 서비스 목적은 판정 기준으로 사용하며 실제 작업 과정과 구분한다.

| 적용 대상 | 통과 조건 |
|---|---|
| 자산 등록 설계 | 기본 공개 범위가 `private`다. |
| 자산 공개·판매 신청 전이 | 명시적인 사용자 선택 없이 공개 또는 판매 신청으로 바뀌는 전이가 0개다. |
| 판매 신청 권한 설계 | `seller` 이외 역할의 신청 허용이 0개다. |
| 판매 검수 상태 설계 | 운영자 검수 없이 승인되는 전이가 0개다. |
| MVP 판매 상태 설계 | `판매 중`·`판매 중지` 상태가 0개다. |

- 해당 기능이 포함된 실행에서는 위 항목을 필수로 검사한다.
- 관련 없는 흐름은 근거를 남겨 `해당 없음`으로 구분하고 통과로 집계하지 않는다.
- 이 검사는 설계의 권한·상태 정의를 확인한다. 실제 서버의 접근 제어 검증과는 별개다.

## 사람 승인

- 사람 승인 지점은 3단계 컨셉 확정 한 곳이다.
- 본인이 내부 관계자와 협의한 결과를 최종 승인으로 입력한다.
- 승인 기록은 해당 컨셉 버전과 연결한다.
- 컨셉 변경 시 기존 승인으로 진행하지 않고 같은 지점에서 재승인받는다.

## 실패와 재시도

- 실패 시 `harness-R3-pipeline.md`에서 정한 단계로 복귀한다.
- 시각 표현의 컨셉 문제는 3단계, 화면 구성·기능 누락은 2단계로 복귀한다.
- 최종 검토의 토큰·컴포넌트·화면 표현 위반은 4단계, 화면 설계 자체의 누락은 2단계로 복귀한다.
- 수정 후 5단계를 다시 실행하며, 컨셉이 바뀌면 3단계에서 재승인받는다.
- 자동 수정은 검사 항목별 연속 2회까지 시도한다.
- 계속 실패하면 원인을 기록하고 중단한다.

## 구현 시 구분할 사항

- 위 내용은 승인된 판정 요구사항이다. Figma 데이터 수집 방식과 필드, 각 규칙의 스크립트 구현 및 테스트는 아직 만들어지지 않았다.
- 판정 규칙의 실행용 단일 기준 파일은 R4에서 정한 `rules.json`이다.
