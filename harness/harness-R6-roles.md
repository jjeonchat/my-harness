# R6 — 하네스 역할

사용자가 모든 기본값으로 진행하도록 승인했다. 이 문서는 역할과 편집 경계, 판정자의 권한, 자연어 트리거를 정의한다. 실제 에이전트나 실행 스크립트는 아직 생성하지 않는다.

## 역할과 편집 경계

경로는 `harness/runs/<실행ID>/` 기준이다.

| 역할 | 담당 작업 | 편집 가능한 폴더 |
|---|---|---|
| 리서처 | 레퍼런스 수집·분석 | `01-research/` |
| 화면 설계자 | 화면 설계 문서와 구조화 데이터 작성 | `02-spec/` |
| 컨셉 디자이너 | 키스크린 제작 | `03-concept/` |
| 디자인 확장자 | 토큰·컴포넌트·전체 화면 디자인 제작 | `04-design/` |
| 판정자 | 증거를 읽고 검사 결과·근거·복귀 단계 반환 | 없음 — 읽기 전용 |

- 각 작업 에이전트는 배정된 실행별 폴더 1개만 편집한다.
- 다른 단계 산출물과 기준 문서는 읽기만 한다.
- Figma도 컨셉용·확장용 영역을 구분해 해당 작업자가 자기 영역만 수정한다.
- `03-concept/approval.json`은 컨셉 디자이너의 편집 범위에서 제외한다. 사용자 승인 내용을 에이전트가 만들어 기록할 수 없다.

## 읽기 전용 판정자

- 판정자는 산출물을 수정하지 않는다.
- 검사 결과, 근거, 복귀 단계를 오케스트레이터에 반환한다.
- 오케스트레이터가 결과를 `05-review/`에 저장하고 해당 작업자에게 수정을 요청한다.

## 자연어 트리거

| 의도 | 트리거 |
|---|---|
| 새 실행 시작 | `[흐름명] 디자인 시작` |
| 중단된 실행 재개 | `[실행ID] 이어서 진행` |
| 특정 컨셉 버전 승인 | `[실행ID] 컨셉 [버전] 승인` |
| 검토 실행 | `[실행ID] 검토` |

- 실행 대상이나 승인 버전이 불명확하면 확인한다.
- `계속해`만으로 컨셉 승인을 기록하지 않는다.
- `approval.json`에는 사용자의 명시적 승인만 오케스트레이터가 기록한다.

## R7에서 확정할 사항

- 오케스트레이터의 승인 기록 권한과 실행 상태 관리 권한을 확정한다.
- 작업 에이전트의 폴더 경계와 구분하여 오케스트레이터가 쓸 수 있는 파일을 명시한다.
- 실행 순서와 조정 규칙을 확인한다. 전체 라운드가 끝난 뒤 `CLAUDE.md` 초안을 별도로 승인받는다.
