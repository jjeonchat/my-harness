# R8 — 검증과 리뷰

사용자가 모든 기본값과 저장을 승인했다. 이 문서는 구현 후 수행할 검증 계획이다. 아직 테스트를 실행하거나 통과했다고 기록한 것이 아니다.

## 첫 검증 흐름

- `내 자산 등록 → 판매 신청` 흐름을 사용한다.
- 비공개 기본값, 판매 권한, 검수 상태를 함께 확인한다.
- 검증용 가상 데이터는 실제 작업 자료와 구분한다.

## 필수 검증 사례

| 사례 | 기대 결과 |
|---|---|
| 필수 조건과 현재 컨셉 승인을 모두 충족 | 통과 |
| 자산 기본 공개 범위가 비공개가 아니거나, 사용자 선택 없이 공개로 전환 | 차단 |
| seller 이외 역할이 판매 신청 가능 | 차단 |
| 운영자 검수 없이 승인되거나, MVP에 판매 중·판매 중지 상태 존재 | 차단 |
| 키스크린 개수·크기 또는 승인된 디자인 규칙 위반 | 차단 |
| 검사 증거 누락·Figma 조회 실패 | 판정 불가, 진행 차단 |
| 승인 누락 또는 변경 전 컨셉의 승인 기록 사용 | 디자인 확장 차단 |
| 중단 후 입력이나 산출물이 변경됨 | 변경된 단계와 이후 단계 재수행 |
| 같은 검사 항목이 자동 수정 2회 후에도 실패하고 재개 요청 | 중단 유지, 재시도 횟수 초기화 금지 |

- 위반 사례가 하나라도 통과하면 하네스 검증 실패다.

## 검증 방식

1. 검증용 구조화 데이터로 판정 스크립트를 검사한다.
2. 실제 Figma 노드에서도 크기, 스타일, 화면 누락을 확인한다.

Figma 접근이 안 되면 해당 검증은 `미실행`으로 남기고 전체 검증 완료로 표시하지 않는다.

## 리뷰 보고서

보고서에는 다음 항목을 기록한다.

- 검사 ID
- 예상 결과
- 실제 결과
- 증거
- 실패 원인
- 복귀 단계

실행별 결과 파일은 `harness-R4-artifacts.md`에서 정한 `05-review/check-results.json`, `05-review/review.md`를 따른다.

## 검증 완료 기준

| 검사 대상 | 완료 조건 |
|---|---|
| 필수 테스트의 예상·실제 결과 불일치 | 0건 |
| 필수 테스트의 미실행·판정 불가 | 0건 |
| 미해결 필수 위반 | 0건 |

위 조건을 모두 충족해야 검증 완료다. 의도적으로 위반을 넣은 사례가 기대대로 차단되면 해당 테스트는 성공이며, 실제 작업물의 위반이 해소됐다는 뜻은 아니다.
