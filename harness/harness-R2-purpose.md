# R2 — 하네스 목적

사용자 승인 완료. 이 문서는 하네스의 목적과 실행 단위, 완료 기준을 정의한다. 하네스 문서는 이 폴더에 모으며, 원본 컨텍스트 문서는 상위 폴더에 유지한다.

## 목적과 범위

| 항목 | 확정 내용 |
|---|---|
| 목적 | 사람이 수행하던 레퍼런스 수집·분석부터 화면 설계, Figma 디자인, 가이드 검토까지를 하네스로 수행한다. |
| 실행 단위 | 사용자 흐름 1개. 실행 시작 시 필요한 화면 목록을 정한다. |
| 매번 달라지는 입력 | 대상 사용자 흐름, 화면 목록, 경쟁사 레퍼런스 |
| 고정 판정 기준 | 승인된 `../prd.md`, `../story-service.md`, `../design.md`. 기준 문서 변경은 별도 승인을 받는다. |
| 작업 과정의 근거 | `../story-workflow.md`. 서비스 판정 기준과 구분한다. |
| 실행자 | 본인 |
| 컨셉 승인자 | 내부 관계자와 협의한 결과를 본인이 최종 승인으로 입력한다. |

## 완료 기준

선택한 흐름의 화면 설계서, 390×844 키스크린 2~3개, 토큰·컴포넌트, 합의한 전체 화면 디자인을 만들고, 컨셉 승인 기록 1건과 필수 검사항목 미통과 0건을 확인하면 완료한다.

| 검사 대상 | 완료 조건 |
|---|---|
| 화면 설계서 | 존재함 |
| 키스크린 | 2~3개이며, 모두 390×844 |
| 디자인 토큰·컴포넌트 | 두 산출물 모두 존재함 |
| 전체 화면 디자인 | 합의한 화면 목록 대비 누락 0개 |
| 컨셉 승인 | 해당 실행의 승인 기록 1건 |
| 필수 검사 | 미통과 0건. 검사항목과 판정 방식은 R5에서 확정한다. |

## 후속 라운드에서 확정할 사항

- 단계별 산출물 파일명과 규칙의 단일 기준 파일은 R4의 `harness-R4-artifacts.md`를 따른다.
- 필수 검사항목, 판정 방식과 `design.md`의 상충 규칙 처리는 R5에서 확정한다.
