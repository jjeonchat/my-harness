# R4 — 하네스 산출물

사용자가 모든 기본값으로 진행하고 하네스 관련 파일을 별도 폴더에 모아 저장하도록 승인했다. 폴더명은 후속 사용자 요청에 따라 `harness/`로 확정했다. 이 문서는 산출물 경로와 규칙의 단일 기준 파일, 재개 방식을 정의한다. 실행용 파일과 스크립트를 지금 생성하는 것은 아니다.

## 폴더 기준

- 하네스 관련 문서와 향후 실행 파일은 프로젝트의 `harness/` 폴더에 모은다.
- 원본 컨텍스트는 상위 폴더의 `../prd.md`, `../design.md`, `../story-service.md`, `../story-workflow.md`를 참조한다. 복제본을 만들지 않는다.
- 아래 `runs/`와 `rules.json` 경로는 `harness/` 폴더 기준이다.

## 실행별 구분

- 실행마다 `runs/<실행ID>/` 폴더를 만든다.
- 실행 폴더의 `input.json`에 대상 흐름, 화면 목록, 제공한 레퍼런스를 기록한다.
- 서로 다른 실행의 파일을 덮어쓰지 않는다.

## 단계별 산출물 파일명

아래 경로는 `runs/<실행ID>/` 기준이다.

| 단계 | 산출물 파일 |
|---|---|
| 1. 수집·분석 | `01-research/references.json`, `01-research/analysis.md` |
| 2. 화면 설계 | `02-spec/screen-spec.md`, `02-spec/screens.json` |
| 3. 키스크린·승인 | `03-concept/key-screens.json`, `03-concept/approval.json` |
| 4. 디자인 확장 | `04-design/tokens.json`, `04-design/components.json`, `04-design/screens.json` |
| 5. 검토 | `05-review/check-results.json`, `05-review/review.md` |

- 디자인 자체는 Figma에 둔다. 대응 파일에는 Figma 노드 링크와 검사에 필요한 구조화 데이터를 기록한다.
- 키스크린 수와 크기 등은 Figma에서 가져온 구조화 데이터를 대상으로 판정한다. 구체적인 데이터 수집·판정 방법은 R5에서 확인한다.

## 규칙의 단일 기준 파일

- 스크립트가 읽는 판정 규칙은 `rules.json` 1개로 모은다.
- 각 규칙에 ID, 판정 대상, 조건, 원문 근거를 기록한다.
- 원문 문서는 유지한다. 충돌하거나 미정인 사항을 에이전트가 임의로 규칙화하지 않는다.
- 실제 규칙 내용은 R5에서 승인받는다.

## 재개 방식

- 중단된 실행을 재개할 수 있게 한다.
- 실행 폴더의 `run-state.json`에 단계 상태와 입력·규칙·산출물의 해시를 기록한다.
- 재개 시 변경이 없고 완료된 단계만 건너뛴다.
- 변경된 단계와 그 이후 단계는 다시 수행한다.
- 컨셉 변경 시 기존 승인으로 진행하지 않는다.

## 후속 확정 사항

- JSON의 세부 필드와 판정에 필요한 데이터 취득·검증 방법은 후속 라운드에서 정한다.
- 현재 저장한 것은 R4 합의 문서이며, `rules.json`, 실행 폴더, 판정 스크립트는 아직 생성하지 않는다.
